## 交互与视觉 / Interaction and visual design

受众为查看离线校园能源样例的分析人员。界面采用浅灰蓝工作台底色、深海蓝文字、青绿色优化曲线、灰蓝色基线、金色光伏；将数据质量放在图表之前，费用、购电量、购电峰值分为三块指标。五个页签分别显示负荷/光伏、购电功率、逐时费用、累计费用与电池 SOC。所有图例和按钮都有中英双语，曲线单位由既有图表准备结果提供。 / The visual hierarchy follows the analyst's workflow: check data, run, then inspect separate metrics and five charts.

指标卡的两个数值顺序固定为“优化 / 基线”，各卡独立标注单位；这种排列不把某一指标的改善暗示为其他指标的改善。 / Each metric card labels its optimized/baseline order and own unit.

横轴保留原输入顺序，在首、中、末标签显示日期、时间与原始 UTC 偏移；不把不同时区的当地时刻误读为统一时区。 / The first, middle and last labels retain the source date, time and UTC offset.

## v0.3.25 工作流分区 / Workflow layout

顶层 `ttk.Notebook` 将桌面流程分为“配置与运行 / Configure & Run”和“历史与报告 / History & Reports”。两个页签从控件创建时就拥有各自的滚动画布；没有在创建后重新挂载 Tk 控件。前者保留 CSV、设备与策略、预设、运行状态、诊断、日志、指标和五张图，后者保留运行根目录、筛选、历史表格、预览、A/B 对比及报告导出。页签选择本身没有配置 trace 或业务回调，不清除结果，也不增加 generation。/ A top-level Notebook separates the two workflows while preserving the existing variables, callbacks and task generation. Each page owns its scroll container from widget creation, and tab selection has no business side effect.

六个预设操作以三列两行排列：第一行为加载、保存为、更新，第二行为导入、导出、删除。历史 `Treeview` 同时连接水平和垂直滚动条，运行标识列继续优先伸缩；A/B 选择仍使用完整历史列表。运行状态位于质量检查、运行和取消按钮下方的独立整行，并按可用宽度换行，不改变状态文本或后台任务语义。/ Preset actions use a 3-by-2 grid, the history table binds both scrollbars, and the run-status label owns a full wrapping row below the action buttons. These are layout changes only.

2026-11-02 的真实 Windows 验收在 `GetDpiForWindow=96`（100%）下观察了默认 1140×780 和最小 900×650 内容区；两个页签、各自纵向滚动、预设按钮、历史滚动条和键盘页签焦点均可见且未出现截断。当前环境未安全切换原生 150%/200% 显示缩放，因此这两档为 `NOT_RUN`，不能由既有程序化 Tk scaling 测试替代。/ Visible acceptance covered the native 100% desktop only. Native 150% and 200% display scaling were not changed and remain NOT_RUN.

## 数据与执行边界 / Data and execution boundary

`python -m gridwise.desktop` 默认选中 `examples/synthetic-day.csv`，也可由用户主动选择本地 CSV。质量由 `import_energy_csv` 判定；任何 `ready=false` 都禁止调度和图表。若输入有效但超过 96 个时段，显示质量结果，交互调度按钮保持禁用，以控制单次 MIP 求解规模。 / User-selected local CSV is accepted, but a failed quality check or the 96-period interactive cap prevents solving.

`dashboard.build_scenario` 只把已验证时序与 `examples/synthetic-day.json` 的购电上界、电池容量、功率、效率及初末能量参数组合；这些参数是**合成设备假设**，不是现场设备参数。v0.3.1 中 `dashboard.run_comparison` 在临时目录内以限时子进程调用既有 `gridwise.cli`，再以独立子进程执行原有 `tools/audit_exports.py`。审计通过后才调用 `prepare_visualization_data`；Tkinter 只读取其 `series`、`metrics`、`units`，没有成本、购电量、峰值或优化公式。临时运行文件在返回前清理，输入 CSV 只读。 / Existing solver, auditor and chart-preparation interfaces remain the calculation authorities; both child processes have bounded execution.

v0.3.1 的检查与运行不占用 Tk 主线程；后台线程只把结果放入队列，主线程更新界面。重复点击运行不会产生第二个任务；更换文件或时间步、关闭窗口会取消在途子进程，旧代次结果不会回填新场景。日志区域可滚动，长错误保留完整文本；三个指标卡分别并排显示优化值与基线值。 / Check and run jobs keep Tk responsive. Input changes and closure cancel in-flight work, stale generations are ignored, and a scrollable log preserves detailed errors.

v0.3.2 的布局检查发现，原先最小 900×650 窗口在 Tk 双倍缩放下会把图表挤到约 1×1 px，长页签和时间标签也会重叠。现在页面可纵向滚动，指标卡根据可用宽度重排；页签不足宽时缩为短名称，图内仍保留完整双语标题和单位。日期、时刻与每个时间戳的 UTC 偏移分两行显示。忙碌条只表示后台任务正在运行，不表示求解进度百分比。 / The page scrolls when scaled content exceeds the window; compact tabs and two-line timestamps protect chart readability without changing the underlying series or metrics.

验证边界：Windows Tk 程序化模拟了 100%、125%、150%、200% 缩放，并在本机观察了默认缩放的真实窗口。未改动系统显示设置；这些模拟结果不能等同于真实 Windows 高 DPI 显示器上的逐档人工验收。 / Tk scaling was exercised programmatically at four factors and the normal Windows window was observed. Native display-scaling changes were not performed.

v0.3.3 预检在本机测得 Python/Tk 创建窗口后的线程 DPI awareness 为 `0`（unaware），只有一台显示器。桌面入口现在于首个 Tk 窗口前读取进程线程的 DPI awareness；仅在 unaware 时使用 Windows `SetProcessDpiAwarenessContext(PER_MONITOR_AWARE_V2)`，已有 awareness 不改动，设置失败明确报错。程序化测试和可见 Tk 烟测确认入口从 `0` 到 `2`，但单显示器 100% 缩放无法验证 `WM_DPICHANGED`、跨显示器移动或原生 125%–200% 显示设置。Tab 可抵达只读日志；Page Up/Down 在非日志焦点时滚动外层页面；重复数据检查不会启动并发质量任务。 / The local process was DPI-unaware after Tk creation and only one monitor was available. The desktop entry point now opts in to per-monitor v2 before the first Tk window, preserving any existing setting. Tests confirm the local awareness change, while native DPI transitions and cross-monitor behavior remain untested. Keyboard access reaches the read-only log, and repeated checks are guarded.

v0.3.4 增加焦点可到达的取消按钮和 Esc 操作。运行中检查/运行按钮禁用；取消仅发出事件并等待工作线程完成清理，随后恢复可用按钮和焦点，不采纳迟到结果。质量检查取消时同样拒收后到结果。窗口关闭时等待已启动任务（包括输入切换后的旧任务）完成资源清理，避免 daemon 线程未退出便结束进程。Windows UI Automation 控件树将多处 Tk 控件暴露为匿名 Pane；这限制屏幕阅读器语义证据，不能从键盘回归推断辅助技术已通过。 / Cancellation and window closing wait for active and stale worker cleanup. The observed UI Automation tree provides limited names and roles for Tk controls; screen-reader acceptance remains open.

v0.3.5 的质量区域增加可见双语标题，所有质量问题完整保留在可聚焦、可滚动的只读日志中；失败质量报告会再次禁用运行按钮，避免旧结果仍可启动。Tk 原生 UI Automation 提供的名称与角色仍有限，视觉文字、Tk 自动化事件和 UI Automation 观察不能替代屏幕阅读器验收。 / The quality log has a visible label and retains every issue for keyboard browsing. A failed check disables dispatch even after an earlier valid result; native Tk UI Automation semantics remain limited.

v0.3.6 的桌面测试发现，直接销毁测试 `Toplevel` 会留下一个尚未执行的 `after` 轮询回调；测试现在走应用自身关闭路径并断言回调取消。这是测试生命周期缺口，尚无证据证明它是此前 `tk_focusNext` 或 Tcl 文件暂不可读异常的根因。独立进程诊断脚本记录运行时库路径和焦点遍历；有限重复成功只能界定本次观测。当前 Windows UI Automation 实测仍将大部分 Tk 子控件列为匿名 Pane，真实物理键盘及屏幕阅读器验收仍需相应环境。 / Test teardown now uses the application's close path and checks cancellation of its scheduled poll. This does not explain the previous intermittent Tk errors. Bounded probes record runtime paths; native UI Automation still exposes most child controls as unnamed Panes.

求解失败、审计失败或图表对齐失败时没有结果卡或图表。UI 不证明输入真实、求解器最优性以外的外部效果，也不接入设备、数据库、校园网络或远程服务。 / Failure leaves no displayed result; no live integration is performed.

图表序列选择函数在无 Tk 环境仍可导入并测试；启动桌面窗口时若 Tk 不可用则明确失败。Linux/macOS 图形桌面及托管 CI 运行尚未验证。 / Chart selection is importable without Tk, while launching the desktop requires a Tk-capable graphical environment; other platforms remain unverified.

## v0.3.12 削峰模式 / Peak-cap mode

优化模式区沿用现有工作台色彩和双语文字，以两个可聚焦单选项明确区分“纯电费优化”和“峰值上限优化”。默认选择纯电费；只有选择削峰后才启用 kW 输入框。输入为空、非数字、NaN、无穷、负数或超过软件边界会在启动后台任务前失败；超过当前合成场景 `grid_max_kw` 的有限数值由控制层明确拒绝。/ Two keyboard-focusable options make the policy explicit. The cap entry is enabled only for peak mode, and invalid values fail before publication.

三个既有指标卡继续并列显示优化方案与无储能基线的 CNY、kWh、kW。新增的策略说明行只显示运行策略证据：设置上限、实际峰值、是否满足，以及可用时相对已校验纯电费运行的电费差额。它明确提示削峰可能增加电费、购电量变化不等于节能。模式切换立即清空旧结果；工作线程只入队，Tk 控件仍只在主线程更新。历史列表标注模式与参数，重启恢复后选择运行会重新校验并恢复策略显示。/ The existing metric cards remain authoritative. A compact policy line shows cap compliance and an optional compatible cost reference without presenting either as energy savings.

## v0.3.15 历史公平对比 / Fair history comparison

运行历史区新增 A/B 两个只读选择框、比较按钮、状态/上下文行和三行指标表。后台控制层重新安全读取两个运行，主线程仅在完整性和公平条件全部通过后显示 CNY、kWh、kW 及带符号的 `B − A`；表格不会把电费变化表述为削峰或节能。上下文同时显示两种策略、峰值上限和实际设备参数。输入、时间步、设备值或运行根目录改变时立即清空旧表；代次不匹配的迟到结果被丢弃。对比表进入现有 Tab 顺序，日志仍可聚焦和翻页。/ Two selectors and a compact table expose a verified comparison without moving any metric formula into Tk. The comparison is invalidated with its input context, and late worker results are ignored by the existing generation mechanism.

## v0.3.16 报告导出 / Report export

历史区在比较表后增加两个明确的双语按钮：导出当前选中的 `VALID` 单次运行，以及导出当前 `VERIFIED / MATCHED` 的 A/B 对比。按钮只表示当前上下文具备导出资格；点击后仍会在工作线程重新安全读取或重新公平比较。选择未完成/损坏运行、切换 A/B、输入、步长、设备或运行根目录都会立即禁用相关按钮。加载任意历史运行开始时先清除旧 A/B 状态，避免设备恢复后短暂显示错误的 `MATCHED`。/ Export eligibility follows the current verified selection, but each export revalidates in the worker. History loading invalidates an old comparison before any device restoration can make its context stale.

保存对话框只在 Tk 主线程打开；HTML 生成和文件发布进入现有 `_start_job` 队列，取消、关闭和 generation 失效沿用同一机制。成功仅显示最终绝对路径；失败保留已有图表/比较供用户查看，但不会把报告写入失败误报为运行失败或导出成功。首版报告使用指标卡和表格，不复制五张 Canvas 曲线，也不增加浏览器组件。/ The main thread owns the dialog and final status. Existing verified views remain visible after an export-only failure, while no failed export is reported as success. The first report version is tabular and does not duplicate the five canvas charts.

## v0.3.18 结构化诊断面板 / Structured diagnosis panel

操作区下方增加常驻的紧凑双语诊断区。无失败时只显示“无活动诊断”；失败时显示类别、阶段、摘要、可用的求解器/终止状态证据和人工检查建议，文字而非颜色承担状态语义。详细证据默认折叠，按键盘可达按钮展开后提供带滚动条的只读 `Text`，保留文本选择、Page Up/Down 及复制能力，不挤占指标卡和图表的常规空间。/ A compact always-present summary communicates diagnosis and trusted solver evidence without color-only meaning. Detailed evidence is collapsed by default and expands into a keyboard-focusable, scrollable read-only text view.

面板只格式化已有 `RunDiagnostic`。新任务和上下文变化会清空旧内容，成功也保持无失败状态；取消分支不调用失败展示，generation 检查继续阻止迟到任务回填。剪贴板异常只更新状态并追加到原日志，不清除诊断。该面板不修改设备值、优化模式、求解约束、历史、A/B 或报告资格规则。/ The panel remains a main-thread presentation adapter. Existing cancellation, generation and fail-closed result behavior remain authoritative, and clipboard errors do not alter diagnostic or model state.
