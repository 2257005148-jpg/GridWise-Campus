## 1. 阶段目标与完成情况 / Objective and completion

- 运行标识 / Run ID
- 状态 / Status
- 优化模式 / Optimization mode
- 峰值上限 / Peak cap (`kW`; `—` when unavailable)

## 3. 设计决策 / Design decisions

1. 筛选先调用 `filter_run_history()`，随后调用 `sort_run_history()`；两者均只处理内存中的 `RunHistoryEntry`。
2. 排序键与顺序：
   - 运行标识：不区分大小写的文本顺序；
   - 状态：`VALID → INCOMPLETE → DAMAGED`；
   - 模式：纯电费 → 峰值上限 → 未知；
   - 峰值上限：按数值排序，缺失值无论升降序均置后。
3. Python 稳定排序保留相同排序键条目的原始枚举顺序。
4. 首次点击新表头为升序，再次点击同一表头切换为降序；当前表头显示 `▲` 或 `▼`。
5. 表格选择仍写入既有 `selected_run`，因此历史加载和单次报告导出不需要新读取路径。
6. A/B 比较下拉框继续使用完整历史快照，不受表格筛选和排序影响。
7. `INCOMPLETE` 和 `DAMAGED` 行显示原错误详情，但加载与报告导出按钮保持禁用。

## 5. 性能与安全边界 / Performance and safety boundaries

- 搜索、筛选、排序和表格重绘仅遍历既有内存快照，不访问磁盘。
- 原 `MAX_HISTORY_ENTRIES=50` 和 `MAX_HISTORY_SCAN=1000` 未修改。
- `VALID / INCOMPLETE / DAMAGED` 分类逻辑未修改。
- 表格不解析 JSON、清单或结果文件，也不计算电费、购电量、峰值等业务指标。
- 选择有效运行后，后续加载仍由原安全读取流程重新校验。
