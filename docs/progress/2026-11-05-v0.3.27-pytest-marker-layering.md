## Marker contract / Marker 契约

Exactly one primary marker is required for every collected item:

- `unit`: isolated in-process logic without Tk, subprocess, a real solver, or
  an independent auditor.
- `gui`: Tk/Tcl widgets, windows, event loops, or desktop state.
- `integration`: filesystem, subprocess, persistence, publication, or
  cross-module behavior.

每个测试必须且只能具有一个主分类：

- `unit`：不使用 Tk、子进程、真实求解器或独立审计器的进程内逻辑。
- `gui`：Tk/Tcl 控件、窗口、事件循环或桌面状态。
- `integration`：文件系统、子进程、持久化、发布或跨模块行为。

Optional risk markers may overlap:

- `solver`: may call the real Pyomo `SolverFactory` or a real solver child.
- `audit`: may start or validate an independent export/history audit workflow.
- `slow`: intentionally repeated, multi-process, timeout, or long-running.

附加风险标记可以叠加：

- `solver`：可能调用真实 Pyomo `SolverFactory` 或真实求解子进程。
- `audit`：可能启动或验证独立导出/历史审计流程。
- `slow`：有意包含重复、多个进程、超时或长时间行为。

`--strict-markers` rejects unknown marker names. `pytest_collection_modifyitems`
rejects missing or multiple primary markers and reports every affected node ID.
Mocked solvers do not receive `solver`; fixture and callback chains that reach a
real boundary do receive the corresponding risk marker.

`--strict-markers` 拒绝未知 Marker。`pytest_collection_modifyitems` 拒绝缺少主分类或具有
多个主分类的测试，并列出所有具体节点 ID。Mock 求解器不标记 `solver`；fixture 和回调链
间接进入真实边界时必须标记相应风险。

## Boundary protection / 入口保护

An autouse test fixture blocks `SolverFactory` for tests without `solver`. It
also installs an isolated temporary `sitecustomize.py` for child Python
processes; an attempted child `SolverFactory` call writes a unique sentinel and
fails the test at teardown. Tests without `audit` reject subprocess commands
that start `audit_exports.py` or `audit_history.py`. The guard directory is in
pytest's system temporary directory, not the repository.

自动 fixture 会阻止未标记 `solver` 的测试调用 `SolverFactory`。Python 子进程通过系统
临时目录中的隔离 `sitecustomize.py` 使用相同保护；子进程尝试调用时写入唯一哨兵文件，
并在 teardown 使测试失败。未标记 `audit` 的测试会拒绝启动 `audit_exports.py` 或
`audit_history.py`。保护文件不写入仓库。

### Safety guard findings / 安全保护发现

The first daily-safe execution was intentionally retained as evidence:

```text
python -m pytest -q -m "(unit or integration) and not solver and not audit and not slow"
```

- Exit code / 退出码: 1
- pytest: `10 failed, 200 passed, 2 skipped, 327 deselected, 8 errors in 4.60s`
- End-to-end time / 端到端耗时: 5.11 s
- Findings / 发现:
  - `chart_case` indirectly used the real solver and needed `solver`.
  - Replacing `subprocess.Popen` with a function broke standard-library
    subclassing; it was changed to a class-preserving guard.
  - CLI preflight tests were shown not to reach `SolverFactory`; child-process
    sentinels now verify the boundary instead of conservatively mislabelling
    those tests.

The GUI-safe guard then found one callback-based omission:

```text
python -m pytest -q -m "gui and not solver and not audit and not slow"
```

- Exit code / 退出码: 1
- pytest: `1 failed, 85 passed, 461 deselected, 1 error in 76.14s`
- End-to-end time / 端到端耗时: 76.78 s
- Finding / 发现: `test_keyboard_browse_check_run_and_chart_tabs` triggered
  the real run button through a keyboard event and therefore required both
  `solver` and `audit`.

An earlier GUI invocation completed outside the initial output-capture window;
its final summary was not recoverable and is recorded as `NOT_RECORDED`, not as
a pass.

## Remaining risks / 遗留风险

- Risk mappings are explicit and collection-enforced, but future tests must be
  classified and reviewed for indirect fixture/callback boundaries.
- The subprocess solver guard covers Python children through `sitecustomize`;
  a future non-Python solver launcher would require a corresponding guard.
- GUI-safe tests still depend on the local Windows Tk runtime. Passing this
  layer does not resolve the historical intermittent Tk/Tcl issue.
- No solver, audit, slow, or complete suite was executed by design.
