# GridWise Campus v0.3.25 Phase 1 — Desktop workflow tabs / 桌面工作流分区

Date / 日期: 2026-11-02

## Scope / 范围

This phase replaces the single long desktop page with two top-level workflow
tabs while preserving the existing widgets, variables, callbacks, generation
isolation, background jobs and cancellation behavior. It changes layout only;
it does not implement the Phase 2 preset-button, history-scrollbar or status-row
redesigns.

本阶段把原有单一纵向长页面划分为两个顶层工作流页签，同时保留既有控件、
变量、回调、generation 隔离、后台任务和取消行为。修改仅限布局；未提前实施
Phase 2 的预设按钮重排、历史表格水平滚动条或运行状态栏调整。

## Implemented layout / 已实现布局

- `配置与运行 / Configure & Run` contains CSV selection and quality checks,
  device and policy controls, local presets, run/cancel/status controls,
  diagnostics, the shared log, current metrics and the five chart tabs.
- `历史与报告 / History & Reports` contains runs-root management, filters,
  the history Treeview, verified preview, A/B comparison and HTML exports.
- The title remains above the workflow tabs so the application identity is
  stable while switching tasks.
- Each workflow owns its scrollable canvas and scrollbar from widget creation;
  no existing Tk widget is reparented after creation.
- Page Up/Down routes to the visible workflow canvas. Text widgets retain their
  own Page Up/Down behavior.

- “配置与运行”页包含 CSV 选择和质量检查、设备与策略、本地预设、运行和
  取消、诊断、共享日志、当前指标及五个图表页签。
- “历史与报告”页包含运行目录、筛选、历史 Treeview、安全预览、A/B 对比和
  HTML 报告导出。
- 应用标题位于工作流页签上方，切换任务时保持稳定。
- 两个工作流在创建控件时即拥有各自滚动画布和滚动条，没有事后修改 Tk
  控件父容器。
- Page Up/Down 作用于当前可见工作流；文本控件继续使用自身翻页行为。

## State and compatibility / 状态与兼容性

Tab selection has no trace or business callback. Tests verify that switching
tabs does not change the CSV path, step, device values, optimization policy,
preset selection, history selection, imported data, current chart object or
generation. A mocked background run remains active across tab changes and
finishes through the existing queue and failure path.

页签选择没有绑定配置 trace 或业务回调。测试确认切换页签不会改变 CSV 路径、
步长、设备值、优化策略、预设选择、历史选择、导入数据、当前图表对象或
generation。模拟后台运行在页签切换期间保持活动，并继续通过既有队列和失败
路径结束。

## Remaining risks and Phase 2 / 剩余风险与 Phase 2

- A visible Windows smoke check is still needed to assess the final visual
  balance of the two tabs; automated Tk assertions do not replace that review.
- The six preset actions remain on one row, the history Treeview still has no
  horizontal scrollbar, and the status text remains beside the run buttons.
  These are intentionally deferred to Phase 2.

  neither reproduces nor claims to fix it.

Phase 2 should remain limited to the three deferred responsive-layout items and
their direct accessibility tests. It should not change workflow state or
business contracts.
