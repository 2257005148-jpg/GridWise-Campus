## 3. 关键实现与设计决策 / Key implementation decisions

### 时间戳 / Timestamps

`import_energy_csv()` 继续使用原有 ISO 8601、UTC 偏移、重复、错序和固定绝对间隔检查；只有全部字段有效的记录才将 `stamp.isoformat()` 写入不可变 `EnergyRecord`。CSV 文件本身不写入。这样场景、求解导出和图表层共享同一规范文本，避免合法 `Z` 或 `+0000` 在求解后被改写成 `+00:00` 而导致对齐失败。/ Existing validation is unchanged; only the in-memory representation is canonicalized after validation.

### 输入摘要 / Input summary

`summarize_energy_input()` 只接受 `ready=true` 且非空的 `ImportResult`。计算使用现有 `Decimal` 数据和统一步长：/ The summary consumes only complete validated records and uses Decimal arithmetic:

- `load_energy_kwh = Σ(load_kw × step_hours)`
- `pv_available_energy_kwh = Σ(pv_kw × step_hours)`

摘要描述输入，不是优化结果、真实性证明或节能量。Tk 仅格式化该函数返回值，没有重复公式。/ The summary describes input only; Tk does not reimplement its formulas.

### 设备与运行边界 / Equipment and run boundaries

CSV 只替换时间戳、负荷、可用光伏和电价；电网功率上限、电池容量、初末 SOC、充放电功率和效率继续来自 `examples/synthetic-day.json`。数据层最多 50,000 时段，桌面交互求解仍限 96 时段。超出 96 时段的有效输入仍显示质量和摘要，但运行按钮保持禁用。/ Equipment assumptions and the 96-period desktop solve limit are unchanged and now explicit.

运行目录继续保存规范化 `scenario.json`，不保存原始 CSV 字节；清单哈希不能证明输入真实性。为避免无必要的格式迁移，本阶段未增加新的运行产物字段。/ Verified bundles still contain the normalized scenario rather than the source CSV bytes; no artifact schema migration was introduced.
