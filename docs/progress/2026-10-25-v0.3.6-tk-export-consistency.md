## 3. 缺陷、修复与保证边界 / Reproduction, fix and guarantee limits

**CLI 普通异常。** 修复前，在四个旧文件存在且第二份替换抛出 `RuntimeError` 时，第一份 `summary.json` 已变为新内容；异常未进入 `except OSError` 回滚，`finally` 又删除暂存目录及恢复副本。新增测试先失败（退出码 1），修复后通过：`_publish` 对普通 Python 异常执行回滚；回滚失败仍保留恢复副本。备份创建失败测试确认此前替换被恢复。清理失败测试分别确认“发布已完成”和“发布未完成”两种明确报错；目录留给人工复核。 / The original `OSError`-only handler lost the previous summary on an injected `RuntimeError`. Regression failed before the fix and passed afterward. Cleanup failures now report the publication state and retained path.

**事务限制。** 受控子进程在首个 `os.replace` 后暂停时，读者看到了新汇总与三份旧文件；杀死该测试自己的子进程后，旧汇总副本保留于暂存目录，主目录仍混合。两个默认写入者竞争一个新目录的合成测试得到退出码 `0` 和 `2`，最终四个文件齐全。单文件替换不等于跨文件原子性；强制终止、断电、非协作写入者和读者无需遵守的完成标记均未被本阶段解决。推荐唯一新目录、CLI 退出码 0、独立审计通过后才交给读者；`--overwrite` 继续保留兼容但不承诺四文件事务。 / A forced-kill experiment directly observed mixed versions. Fresh per-run directories are the recommended current workflow; overwrite is not a bundle transaction.

**Tk 测试生命周期。** 复现：`EnergyDesktop` 创建后存在一个 `after` 轮询回调；测试直接 `Toplevel.destroy()` 后回调仍待处理，直到后续事件循环运行。测试夹具现在调用应用自身 `_on_close()`，并断言回调被取消。它是确定的测试清理问题，但没有证据表明它导致先前 `tk_focusNext` 或 Tcl 文件暂不可读异常。诊断脚本记录 Python/Tcl/Tk 版本、`info library`、`auto_path`、实际 `tk_library`、`tk.tcl`、`icons.tcl`、`ttk/ttk.tcl`、`ttk/scrollbar.tcl` 路径与可读性、焦点遍历次数、子进程退出码和异常堆栈。 / The test callback leak is real; causation for the intermittent runtime error is not established.
