# GridWise Campus v0.3.24 Phase 2 — Desktop preset import/export / 桌面端预设导入与导出

Date / 日期: 2026-11-02

## Scope / 范围

This phase connects the Phase 1 preset exchange APIs to the existing Tk preset
area. It does not change the exchange format, model, solver, data layer, CLI,
auditors, run artifacts, reports, or `desktop.json`.

本阶段只把 Phase 1 的预设交换 API 接入现有 Tk 预设区域；未改变交换格式、
模型、求解器、数据层、CLI、审计器、运行产物、报告模块或 `desktop.json`。

## UI implementation / UI 实现

- Added `导入 / Import` and `导出 / Export` buttons beside the existing preset
  CRUD controls.
- Import remains available while idle. Export, load, update and delete require
  a selected preset. All preset operations are disabled while a background job
  is active or the window is closing.
- All UI mutation remains on the Tk main thread. No new worker, queue, callback
  or generation mechanism was introduced.

## Import workflow / 导入流程

1. `askopenfilename()` selects one JSON file.
2. `load_preset_exchange()` performs all exchange-format and file validation.
3. The current local preset store is reloaded.
4. A case-insensitive name collision prompts the user to cancel or enter a new
   name. Existing presets are never silently overwritten.
5. `create_preset()` adds the validated configuration with the fresh ID created
   by Phase 1 and enforces the existing duplicate and 100-preset limits.
6. `save_presets()` atomically saves the new collection.
7. Only after successful persistence is the combobox refreshed and the new
   preset selected.

Cancel, validation failure, rename failure and save failure leave the persisted
store and current selection unchanged. Successful import does not call
`_configuration_changed()`: it does not load device values, increment the
generation, clear the checked CSV, metrics, charts, history state or report
eligibility, and it does not start solving, auditing or publishing.

## Export workflow / 导出流程

1. Export requires a selected in-memory preset.
2. Before showing the save dialog, the local store is reloaded and the stable
   ID must still exist. A missing ID disables export and fails closed.
3. `asksaveasfilename()` selects a JSON target with overwrite confirmation
   disabled.
4. `export_preset_exchange()` reloads the store again and performs Phase 1's
   atomic, no-overwrite hard-link publication.
5. Success reports the full exported path. Existing targets, unsupported hard
   links and other Phase 1 failures are shown through the existing preset error
   path without changing the current selection or runtime state.

## Remaining risks / 遗留风险

- Manual native file-dialog usability and button layout were not visually
  inspected in this phase.
- Preset import/export is intentionally synchronous and assumes the existing
  128 KiB bound; it is not a general large-file workflow.
- A separately running local process can still modify the preset store between
  UI checks. The core APIs revalidate and fail closed, but no multi-process
  writer lock is provided.
- Phase 3 and any batch import, overwrite workflow or format migration remain
  outside this phase.
