# GridWise Campus v0.3.25 — Desktop workflow layout / 桌面工作流布局

Date / 日期: 2026-11-02

## Scope / 范围

This report closes the three v0.3.25 phases: two independent workflow tabs,
responsive action areas, and visible Windows acceptance. No optimization,
audit, artifact, persistence or report contract changed.

本报告收尾 v0.3.25 三个阶段：双工作流页签、操作区响应式调整及真实 Windows
可见验收。优化、审计、运行产物、持久化和报告契约均未改变。

## Implemented layout / 已实现布局

- `配置与运行 / Configure & Run`: CSV quality, device and policy controls,
  scenario presets, run/cancel/status, diagnostics, log, metrics and charts.
- `历史与报告 / History & Reports`: runs-root controls, filters, history
  Treeview, verified preview, A/B comparison and HTML exports.
- Each workflow owns its vertical scroll container. Tab switching has no
  configuration trace, generation increment or result invalidation.
- Preset actions use two rows: Load / Save as / Update, then Import / Export /
  Delete. Existing controls, commands and busy-state rules are reused.
- The history Treeview binds vertical and horizontal scrollbars. The run-ID
  column remains the stretchable column.
- Run status occupies a full row below the three action buttons and wraps to
  the available width.
- The History & Reports tab mirrors the same shared run-status variable in a
  fixed responsive label above its scrollable content, so history refresh,
  preview, comparison and report-export feedback remains visible without
  changing status semantics or task state.

- “配置与运行”包含 CSV 质量、设备和策略、场景预设、运行/取消/状态、诊断、
  日志、指标和图表。
- “历史与报告”包含运行根目录、筛选、历史 Treeview、安全预览、A/B 对比和
  HTML 报告导出。
- 两个工作流各自拥有纵向滚动容器；切换页签不触发配置 trace、不增加
  generation，也不清除结果。
- 预设按钮按“加载/保存为/更新”和“导入/导出/删除”两行排列，继续复用原按钮、
  回调和忙碌状态规则。
- 历史 Treeview 同时绑定纵向和水平滚动条，运行标识列优先伸缩。
- 运行状态在三个操作按钮下方独占整行并按可用宽度换行。
- “历史与报告”页通过滚动内容上方的固定响应式标签镜像同一个运行状态变量，
  因此刷新、预览、A/B 对比和报告导出的反馈在当前页始终可见，状态语义与任务
  状态保持不变。

## P1 status-visibility follow-up / P1 状态可见性修复

Root cause: `self.status_label` was created only under Configure & Run. History
refresh, metric preview, A/B comparison and HTML export correctly updated the
shared `self.status`, but History & Reports had no label bound to that variable.

Minimal fix: one responsive `history_status_label` was added to the history
workflow and bound directly to the existing `self.status`. No `StringVar`,
callback, worker, generation transition, status text or business path was
added or replaced. The Configure & Run status label remains in place.

根因：`self.status_label` 仅位于“配置与运行”页。历史刷新、指标预览、A/B 对比
及 HTML 导出虽然正确更新共享的 `self.status`，但“历史与报告”页没有绑定该变量
的标签。

最小修复：历史工作流新增一个响应式 `history_status_label`，直接绑定既有
`self.status`。没有新增或替换 `StringVar`、回调、后台任务、generation 变化、
状态文本或业务路径；配置页原状态标签继续保留。

Actual red/green evidence / 实际红绿证据:

1. Before implementation:
   `python -m pytest -q tests/test_desktop_ui.py -k "history_workflow_mirrors_shared_status_without_changing_generation"`
   — exit `1`; `1 failed, 86 deselected`; pytest `1.36s`, measured `1.94s`.
   Failure: `EnergyDesktop` had no `history_status_label`.
2. After implementation, the same command — exit `0`;
   `1 passed, 86 deselected`; pytest `0.89s`, measured `1.32s`.
3. Direct regression selection covering both tabs, generation isolation, long
   status layout, history preview, A/B comparison and report export:
   `python -m pytest -q tests/test_desktop_ui.py -k "workflow_tabs_separate_current_run_and_history_without_mutating_state or workflow_tab_switch_during_background_run_preserves_job_generation or history_workflow_mirrors_shared_status_without_changing_generation or long_run_status_uses_full_row_without_squeezing_action_buttons or history_preview_button_shows_verified_metrics_mode_and_cap or history_comparison_controls_call_controller_and_show_verified_table or report_export_controls_use_verified_background_workflows"`
   — exit `0`; `7 passed, 80 deselected`; pytest `6.63s`, measured `7.05s`.

The regression confirms both labels use the same `self.status`, status changes
appear on both pages, tab switching does not replace that variable or increment
generation, and the four history operations expose their existing status text

该回归确认两个标签绑定同一个 `self.status`，状态变化在两个页签同步显示；切换
页签不会替换该变量或增加 generation；四类历史操作的既有状态文本均可在历史页
看到。

### Second P1 fixed-status follow-up / 第二次 P1 固定状态栏修复

The first P1 change placed `history_status_label` inside `history_outer`, which
is the window owned by the scrollable history canvas. The label shared the
correct variable but scrolled out of view when the user reached preview,
comparison or report-export controls near the bottom of the page.

The label is now a direct child of `history_tab`. A dedicated history-content
frame below it owns the existing canvas and vertical scrollbar; `history_outer`
and every history control remain inside that canvas. The label retains the same
`self.status` and existing responsive wrap binding. No status variable,
business callback, worker, generation transition or history operation changed.

第一次 P1 修改把 `history_status_label` 放在可滚动历史画布持有的
`history_outer` 中。它虽然绑定了正确变量，但用户滚到页面底部的预览、A/B 对比
或报告导出区域时，标签也会滚出视口。

修复后，状态标签成为 `history_tab` 的直接子控件；其下方独立历史内容容器继续
持有原画布和纵向滚动条，`history_outer` 与全部历史控件仍在画布内。标签继续使用
同一 `self.status` 及既有响应式换行绑定，没有新增状态变量、业务回调、后台任务、
generation 变化或历史操作逻辑。

Actual red/green evidence / 实际红绿证据:
