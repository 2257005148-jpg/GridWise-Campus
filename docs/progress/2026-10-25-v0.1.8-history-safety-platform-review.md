## 3. 关键实现、设计决策与 Bug / Implementation, decisions and bugs

- 初始 HEAD 为 `6822baa95341d5c3fddae99496e60295969cea77`，它是指定代码基线 `7d9600f458a7aa17f1722e197fc0442be5faf204` 的 v0.1.7 报告后继提交。初始只存在五份更早的未跟踪报告，无远程、仅主工作树；未重置。 / The requested base was an ancestor of the actual report-only HEAD; no reset was used.
- **Git 钩子风险 / Hook risk:** 修复前，历史 worktree 检出可能执行由仓库本地 `core.hooksPath` 指定的 `post-checkout` 钩子，而审计器摘要验证发生在检出之后。复现条件是受控合成仓库配置一个写标记文件的钩子。修复后检出命令局部设置专用空 `core.hooksPath` 和 `core.fsmonitor=false`；回归测试确认标记未出现且审计成功。仍不把任意外来仓库视为可信执行环境。 / Checkout now disables repository hooks and fsmonitor before the reviewed script is inspected.
- **原件竞态 / Artifact race:** 修复前历史脚本直接读取四个原件，前后 SHA-256 只能发现持久变化。现在先核对每个原件的 SHA-256，再生成受 32 MiB 上限约束的字节快照并再次比对；历史脚本只读取快照，结束时再次核对原件。快照前替换阻止执行；审计期间持续替换使整体失败。若替换后在最终散列前恢复原字节，两个观察点仍可能相同；因此 `artifacts_unchanged=PASS` 不证明全过程没有短暂修改。 / Snapshots stabilize the audited bytes; endpoint hashes cannot prove no transient replace-and-restore.
- **状态准确性 / Status accuracy:** 原件在快照前变化时，`arithmetic_physics` 保持 `NOT_RUN`；若历史算术已运行而原件随后变化，整体算术结论变为 `FAIL`。工作树创建失败不执行历史脚本；清理失败报告 `FAIL` 并保留受控临时路径。 / Not-run and failed are distinguished.
- 历史 `core.py`、锁、已审查标准库审计器的 Git blob 与汇总元数据在检出前核对；检出后再次检查 HEAD、审计器摘要和锁文件原始字节，随后才执行 `python -I` 历史审计器。历史 Pyomo 模型不执行。测试仓库的传递依赖版本按当前安装元数据生成；CI 采用完整 Git 历史供旧 blob 测试读取。 / Review and byte checks precede the only allowed historical script.
- `--repo` 仍是信任边界：仅对本项目和受控合成临时仓库使用。局部 Git 设置减少已识别的钩子/属性/换行风险，不构成对恶意仓库或宿主机配置的完整沙箱。 / The prototype is not an arbitrary-repository sandbox.

## 6. 关键数值及计算依据 / Numeric results and basis

同一合成 JSON、六个 1 小时时段、相同负荷/光伏/电价与 `max(grid_kw)` 峰值定义下：储能电费 **131.01108033240996 元**（显示 131.01）、购电 **247.02216066481995 kWh**、峰值 **90 kW**；无储能基线电费 **162.50 元**、购电 **240 kWh**、峰值 **60 kW**。电费降低约 31.49 元，而购电量增加约 7.02 kWh、峰值增加 30 kW。 / Lower cost does not imply lower energy or peak.

当前独立审计器从原始 JSON 与两份 CSV 逐时重算输入回显、功率、SOC、弃光、电费、电量和峰值，检查前不舍入，绝对容差 `0.00001`；历史原型在旧结果上使用固定摘要的 v0.1.5 审计器。两者只验证给定合成文件与对应规则一致，不证明输入真实或求解最优。 / Arithmetic consistency is narrower than authenticity or optimality.

## 7. 数学模型与独立校验 / Mathematical model and independent check

**静态审查，未改动 / Static review, unchanged:** 决策变量 `grid[t]`, `charge[t]`, `discharge[t]`, `pv_used[t]`, `soc[t]`、二元 `mode[t]`；目标最小化 `Σ grid[t] × price[t] × step_hours`。功率平衡 `grid + discharge + pv_used = load + charge`；SOC 递推 `soc[t] = prior + step_hours × (ηc × charge − discharge/ηd)`；约束含初始/终端 SOC、容量、功率、光伏上限、充放电互斥及最优求解状态。无储能基线禁用充放电。 / Cost-only dispatch and the comparable baseline were preserved.

**动态校验 / Dynamic check:** 当前合成结果的独立逐时审计通过；旧结果的历史上下文与历史算术通过，当前上下文按预期失败。未执行历史求解器或真实场景。 / Historical results were audited, not re-solved.
