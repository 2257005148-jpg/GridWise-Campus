# GridWise Campus v0.3.17 阶段报告 / Stage Report

日期 / Date: 2026-10-28

## 1. 阶段目标与完成情况 / Goals and completion

本阶段实现了轻量、只读的运行失败诊断，并修复普通桌面任务“结果已完成并入队、但 UI 尚未轮询时仍接受取消”的状态不一致。优化目标、物理约束、CLI 参数、运行产物格式和独立审计器均未改变。/ This stage adds conservative display-only run diagnostics and linearizes desktop cancellation with job completion. The optimization model, CLI, bundle format and auditor remain unchanged.

已完成：

- 新增冻结的 `RunDiagnostic`、失败类别和执行阶段；
- 只依据结构化运行阶段/原因及严格可信的 CLI 终止格式分类；
- 证据不足或诊断自身失败时返回 `UNKNOWN`，保留原异常引用和异常链；
- 参数建议仅显示，不修改 CSV、设备参数、SOC、效率或峰值上限；
- `RunArtifactError` 增加仅存在于内存的阶段、原因、退出码及 stdout/stderr 字段；
- 普通任务使用小型完成/取消门闩，覆盖运行中取消、已入队迟到取消和显示后取消；
- 失败清除当前图表、指标、运行选择及单次报告导出资格；
- 真实不可行情景探针和本阶段定向测试通过；最终完整测试复现了 1 次既有 Tk/Tcl 间歇性焦点异常，因此本阶段不能声明全量回归全绿。

## 3. 关键设计决策 / Decisions

1. `INFEASIBLE` 必须有求解阶段及严格的 `solver_status, termination_condition` 证据；任意文本包含 infeasible 不足以分类。
2. 当前 HiGHS 对真实不可行情景返回 `solver_status=error`、`termination_condition=infeasible`，因此分类以 termination condition 为准，不能把 status `error` 单独解释为求解器崩溃。
3. 审计阶段、产物阶段及取消原因由 `RunArtifactError` 的进程内属性传递，不写入运行文件，保持格式兼容。
4. 桌面没有更换线程/队列框架；门闩只线性化用户取消和工作线程完成入队。
5. 所有建议均为人工检查方向，不能声明根因，也不会自动改变参数或重试。

## 5. 核心模型与审计边界 / Model and audit boundary

本阶段未修改 `src/gridwise/core.py`、`src/gridwise/data.py`、`src/gridwise/cli.py`、`tools/audit_exports.py` 或 `tools/audit_history.py`。纯电费目标、峰值上限约束、功率平衡、SOC、效率、互斥、终端 SOC 及独立审计容差保持不变。/ Mathematical and independent-audit contracts are unchanged.

真实不可行探针使用合法但不可行的设备配置：`grid_max_kw=0`, `initial_kwh=0`, `terminal_kwh=0`, charge/discharge power `0`。诊断只报告求解器的不可行终止证据；没有宣称某个单一参数是根因，也没有修改输入。

## 7. 未解决问题、风险与 NOT_RUN

- `UNKNOWN` 仍需要人工读取日志；诊断不会猜测未知异常。
- CLI 的文本协议没有变成通用机器协议；只有严格匹配当前可信错误格式时才提取 status/termination。
- 诊断不能证明输入真实、求解最优或产物完整；成功路径仍依赖独立审计和安全读取。
- 强制终止、断电及恶意本机写入者不在此门闩保证范围内。
- Linux、macOS、托管 CI、屏幕阅读器和真实校园设备：`NOT_RUN`。
- 本机符号链接动态用例因权限不足跳过；静态拒绝路径保留。
- 历史 Tk/Tcl 间歇焦点异常在最终完整测试中再次复现：`tk_focusNext` 加载 `focus.tcl` 时报告文件不存在；隔离重跑通过，根因仍为 `UNKNOWN`。按阶段边界仅记录证据，未修改 Tk 相关代码。
