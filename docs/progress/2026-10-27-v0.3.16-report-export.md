## 3. 关键实现与设计决策 / Key decisions

1. **验证后格式化 / Verify then format**：报告入口不信任当前 UI 缓存。单次运行重新安全读取，对比报告重新执行完整公平比较；任一环节失败都没有部分报告。
2. **不复制指标逻辑 / No duplicate business logic**：报告只读取控制层返回的 CNY、kWh、kW 和 `B − A`。公式仅作为口径说明文本出现。
3. **单文件发布边界 / Single-file publication boundary**：先生成完整字节，再在目标目录写私有临时文件。此机制不宣称抵御恶意本机写入者、检查/替换竞态或断电。
4. **桌面代次隔离 / Desktop generation isolation**：文件对话框由主线程打开；验证和写入进入现有工作线程。输入、步长、设备、运行根目录或 A/B 选择改变会使相关导出资格失效。
5. **历史加载先失效 / Invalidate before history restore**：`_load_history()` 在任何设备参数恢复或后台读取前调用 `_clear_history_comparison()`，避免上下文切换期间显示旧结论。

## 4. Bug 复现与修复 / Bug reproduction and fix

### v0.3.15 历史比较残留

- 复现：先比较同设备的纯电费与 55 kW 运行，再加载设备参数不同的第三个历史运行。
- 修复前：新增端到端测试失败；`history_comparison` 仍是旧 `HistoricalRunComparison`，界面仍可显示 `VERIFIED / MATCHED`。
- 修复：历史加载入口立即清除比较对象、状态、上下文、表格和导出资格；保留原设备恢复和 generation 行为。
- 修复后：单用例 `1 passed in 6.50s`，三项新增桌面回归 `3 passed in 10.70s`。

### Tk Notebook 焦点观察

- 非交互管道中的桌面组合测试曾为 `48 passed, 1 skipped, 1 failed`；失败是既有键盘页签用例生成 `<Right>` 后页签未切换。隔离非交互复跑仍失败。
- 同一用例在 PTY/交互宿主通过；运行时检查确认焦点对象为 Notebook、`TNotebook` 的 `<Right>` 类绑定存在，最小应用探针可切换页签。完整桌面套件在 PTY 为 `43 passed`。
- 结论：宿主焦点相关，根因仍为 **UNKNOWN**；没有添加重试、宽泛异常捕获或删除断言。该历史 Tk/Tcl 风险未被最终全绿覆盖。

### 报告取消与最终发布竞态续修 / Cancellation-publication race follow-up

- 复现：报告完成 `fsync` 并进入发布阶段后触发取消。修复前的定向运行时探针返回成功路径且 `TARGET_EXISTS=True`，而桌面会依据 `_cancel_requested` 显示“已取消”。
- 红测：新增公共发布接口测试，在 `fsync` 后暂停并请求取消；修复前因缺少同步门闩而得到 `2 failed in 0.19s`。
- 修复：新增兼容 `threading.Event` 的 `ReportCancellation`。接受取消与最终 `os.replace` 竞争同一锁；取消先提交时替换不执行，发布先提交时迟到取消返回 `False`。桌面仅对两个报告任务使用该门闩，原求解、审计、历史任务线程模型不变。
- 结果：无旧目标和允许覆盖旧目标两种取消场景均通过；后者证明原字节不变。发布先提交的桌面回归证明迟到取消不会显示虚假“已取消”，随后显示实际导出成功。
- 保证边界：门闩只线性化同一进程、协作调用方的取消与最终替换；不抵御恶意本机写入者、断电或进程强制终止。/ The gate provides an in-process cooperative linearization point, not crash or adversarial-writer safety.
