## 4. 格式、实现与保证边界 / Format, implementation and limits

新入口 / New entry point: `python -m gridwise.run_artifacts publish SCENARIO.json RUNS_PARENT`；`python -m gridwise.run_artifacts verify RUN_DIR`。Python API 为 `publish_run()` 与 `read_verified_run()`。旧 CLI 参数与输出保持不变。每个目录命名 `run-<UUID4>`，固定包含 `scenario.json`、`optimized.csv`、`baseline.csv`、`summary.json`、`grid-purchase.svg`、`manifest.json`、`COMPLETE`。 / The new interface is opt-in and creates a unique run directory with exactly seven entries.

清单格式版本 `1`，对五个数据文件按固定顺序记录文件名、字节数、小写 SHA-256；元数据包含模型版本、Git 提交及源码状态、场景指纹、求解器名称与状态。`COMPLETE` 只绑定清单字节摘要，不能单独证明可信。清单 64 KiB、标记 80 bytes、单文件 32 MiB、总数据 96 MiB 上限；拒绝绝对路径、路径穿越、重复名、重复 JSON 键、非有限 JSON、符号链接与 junction。读取端返回已校验的字节，并对读取期间可见的身份/大小/修改时间变化及清单/标记变化失败关闭。 / The reader checks a strict bounded schema and returns checked bytes rather than paths.

发布先调用旧 CLI 生成结果，对五个暂存文件在审计前后比较 SHA-256，再用**未修改的独立审计器**核对同一场景与两份 CSV、汇总 JSON；任一文件跨审计变化即失败。审计成功后生成/复核清单，最后创建完成标记。失败留下本次生成的未完成目录供定位，不删除任何未知目录；最终校验失败会撤销本次创建的标记。 / File digests must stay fixed across the independent audit before completion. Incomplete generated directories are retained for diagnosis.

**保证边界：** 单文件 `os.replace` 不是多文件原子事务；目录在生成期间可见，协作读者必须使用安全读取接口。并发读取拿到各自校验过的字节。强制终止可能留下未完成目录；若发生在完成标记写入之后，运行可能已经提交。未验证断电后的目录持久性，也不能防御能同时篡改文件、清单和标记的本机恶意写入者。哈希、Git 提交与 `optimal` 文本字段均不是输入真实性或最优性的独立证明。 / This is a cooperative integrity contract, not a power-loss transaction, signature or authenticity proof. Full design: [run artifact contract](../run-artifact-contract.md).
