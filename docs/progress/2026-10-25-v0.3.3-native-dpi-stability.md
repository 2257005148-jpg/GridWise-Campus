## 3. 问题、复现与修复 / Reproduction and fixes

1. **DPI 初始化 / DPI setup:** 修复前独立进程在 Tk 窗口创建前后均读得 DPI awareness `0`，虽然能改 `tk scaling`，仍不能据此认为 Windows 原生高 DPI 已启用。回归先失败 `after=0`。入口现在创建任何 Tk 窗口前读取 awareness；仅值为 `0` 时调用 `SetProcessDpiAwarenessContext(PER_MONITOR_AWARE_V2)`，已有非零设置不覆盖，API 失败明确抛错。本机复测从 `0` 变为 `2`，窗口实际映射成功；预先设置系统感知 `1` 的独立进程保持 `1`。 / The process now opts in early and preserves an existing policy.
2. **日志与滚动 / Log and scrolling:** 修复前 Tab 焦点跳过禁用的只读日志，按钮焦点下 Page Down 不滚动页面；两项断言先失败。日志现在显式加入焦点顺序，Page Up/Down 在非日志焦点时滚动外层页面；日志自身保留默认翻页。键盘回归用空格触发文件选择、检查、运行，方向键切换图表页签。 / Keyboard workflow and read-only log navigation passed Tk event tests.
3. **重复检查 / Duplicate quality checks:** 修复前连续两次调用检查实际启动两个后台导入任务，回归先失败 `calls=2`。现在检查任务进行时忽略重复请求，并在任务期间禁用检查按钮、结束时恢复。 / One in-flight quality job is retained.

以上三个新增回归组首次运行 `3 failed, 14 deselected`，修复后 `3 passed, 14 deselected`。键盘全流程和既有 DPI 设置保护测试随后新增并通过。 / The defects were reproduced before the fixes.

Microsoft 文档说明进程 DPI 设置须在创建窗口前完成，且已有设置不能在该进程内随意改动：[设置默认 DPI awareness](https://learn.microsoft.com/en-us/windows/win32/hidpi/setting-the-default-dpi-awareness-for-a-process)、[WM_DPICHANGED](https://learn.microsoft.com/en-us/windows/win32/hidpi/wm-dpichanged)。本机只有一台报告中的显示器，尚无 `WM_DPICHANGED` 的实测证据。 / The local test does not establish cross-monitor handling.

## 5. 数值、模型和审计边界 / Results, model and audit scope

同一 `examples/synthetic-day.json` 输入、时间步和峰值定义下：优化方案电费 **131.01 CNY**、购电量 **247.02 kWh**、购电峰值 **90.00 kW**；无储能基线分别为 **162.50 CNY**、**240.00 kWh**、**60.00 kW**。独立导出审计通过。电费下降同时伴随本例购电量和峰值上升，不构成削峰或节能证据。 / Cost improved while energy and peak rose in this synthetic scenario.

`src/gridwise/core.py`、`src/gridwise/data.py`、`tools/audit_exports.py`、`tools/audit_history.py` 未改；目标仍为 `min Σ grid_kw × price_cny_per_kwh × step_hours`。UI 继续读取既有图表准备结果，没有自行重算优化或指标。 / The mathematical and audit contracts remain unchanged.

## 6. 风险、未执行与下一阶段 / Risks, NOT_RUN and next step

- **NOT_RUN:** Windows 原生 125%、150%、200% 显示档位、不同 DPI 物理显示器间拖动、`WM_DPICHANGED` 后字体/图表/页签逐项观察；本机只报告一台显示器，也未修改系统设置。 / Native DPI transitions need another test environment.
- **NOT_RUN:** 物理键盘人工辅助技术验收、屏幕阅读器语义检查、长时间耐久性、Linux/macOS GUI、托管 CI、真实设备和数据。 / These were not inferred from synthetic tests.
- **静态风险 / Static risk:** Tk 8.6.12 在真实不同 DPI 显示器上的每窗口布局响应仍需实测；应用的早期 DPI 设置仅证明当前进程感知模式，不证明每显示器 UI 质量。 / Process awareness alone does not prove per-monitor visual behavior.
- **下一阶段 / Next:** 在获准的双显示器或可切换原生缩放环境中，观察 100%–200% 窗口移动、焦点与五图边界；记录每台显示器的 Windows DPI、Tk scaling 和截图。 / Record genuine monitor-transition evidence before claiming native acceptance.
