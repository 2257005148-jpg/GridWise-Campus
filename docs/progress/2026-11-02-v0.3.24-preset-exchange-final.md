## Static API consistency / API 静态一致性

The documentation was compared directly with `scenario_presets.py` and the
desktop preset callbacks. The following statements match the implementation:

- Exchange documents use `document_type="gridwise-scenario-preset"`, integer
  `format_version=1`, and one exact `preset` object with a name, eight device
  values and one optimization policy.
- Internal UUIDs are omitted from export; `load_preset_exchange()` creates a
  fresh ID only after strict validation. Input and output are limited to
  128 KiB UTF-8 JSON.
- Desktop import handles case-insensitive name collisions through cancel or
  rename, inserts through existing CRUD, saves atomically and refreshes the
  list only after persistence. It does not apply parameters or start solving.
- Export rereads the saved stable ID, writes and fsyncs a same-directory private
  temporary file, then uses `os.link()` for atomic no-overwrite publication.
  No overwrite fallback is used when the target exists or hard links are not
  supported.
- The documented limitations match the code: no multi-process merge or writer
  lock, no parent-directory fsync/power-loss durability guarantee, and no
  sandbox claim against a privileged process replacing ancestor directories.
