# GridWise Campus v0.3.19 Phase 1 — 历史运行搜索与筛选 / Run-history search and filters

日期 / Date: 2026-10-28
阶段性质 / Stage type: 本地实施与验证，未提交 / Local implementation and verification, not committed

## 1. 阶段目标与完成情况 / Objective and completion

本阶段在不改变历史产物、安全读取、优化模型或审计器的前提下，为已有历史运行列表增加了：

- 按运行标识进行不区分大小写的搜索，并忽略查询首尾空白；
- `VALID`、`INCOMPLETE`、`DAMAGED` 状态筛选；
- 纯电费与峰值上限优化模式筛选；
- 搜索、状态和模式的组合筛选；
- 清除筛选并恢复完整列表；
- 无匹配项和无历史记录的双语提示；
- 新筛选控件的键盘焦点回归。

All search and filter operations use the already enumerated in-memory snapshot. Only the existing explicit refresh action scans the runs root.

## 2. 新增和修改文件 / Added and modified files

- `src/gridwise/dashboard.py`：新增 `filter_run_history()` 纯函数以及允许的状态、模式集合。
- `src/gridwise/desktop.py`：新增搜索框、状态/模式筛选框、清除按钮、结果计数和空结果提示；A/B 选择仍使用完整历史快照。
- `tests/test_dashboard.py`：新增运行标识、状态、模式和组合筛选控制层测试。
- `tests/test_desktop_ui.py`：新增内存筛选、清除筛选、空结果、无额外扫描和无效状态语义测试；扩展键盘焦点覆盖。
- `docs/progress/2026-10-28-v0.3.19-history-search-filter.md`：本报告。

## 3. 关键实现与设计决策 / Key implementation decisions

1. `filter_run_history()` 只接收 `RunHistoryEntry` 集合并保持输入顺序，不访问文件系统。
2. `list_run_history()`、`MAX_HISTORY_ENTRIES=50` 和 `MAX_HISTORY_SCAN=1000` 未修改。
3. `VALID / INCOMPLETE / DAMAGED` 的分类仍只由原历史枚举及 `read_verified_run()` 决定；筛选不会提升或改变可信状态。
4. 桌面筛选仅影响“读取所选”列表。A/B 比较下拉框继续保留全部历史记录，避免改变既有比较工作流。
5. 被筛选掉的当前选择会立即清空，同时禁用加载和单次报告导出，避免隐藏选择继续生效。
6. 本阶段未增加指标预览、排序、运行时间字段、数据库、缓存文件或依赖。

## 5. 测试结果 / Test results

### 实际动态验证 / Dynamically verified

- 定向验收：35 passed、0 failed、77 deselected。
- 完整 pytest：448 passed、0 failed、2 skipped。
- 跳过项：CLI 输出符号链接拒绝测试和 HTML 报告符号链接拒绝测试；当前 Windows 进程缺少创建符号链接所需权限，错误均为 `WinError 1314`。两项未计为通过。
- Tk/Tcl 历史间歇异常本轮未出现，但其根因仍为 `UNKNOWN`，本阶段不声称修复。

### 静态审查 / Static review

- 搜索/筛选回调未调用 `list_run_history()`、`read_verified_run()` 或任何 JSON/清单读取代码。
- `core.py`、`data.py`、`run_artifacts.py`、两个独立审计器均未修改。
- A/B 比较、历史加载和报告导出仍引用原始 `_history_entries` 快照。

### 未执行 / NOT_RUN

- 人工可见 GUI 烟测和截图：`NOT_RUN`；本阶段使用 Windows Tk 自动化回归。
- Linux、macOS 和托管 CI：`NOT_RUN`。
- 接近 50 个运行、1000 个目录项的性能压力测量：`NOT_RUN`；实现保留既有上限，并通过 mock 证明筛选不触发扫描。
- 真实校园数据、设备或外部服务：`NOT_RUN`，且不在范围内。

## 6. 性能与安全边界 / Performance and safety boundaries

- 磁盘扫描只发生在用户明确点击“刷新运行”时。
- 搜索、筛选和清除筛选的复杂度为当前内存快照的线性遍历，最大返回数量仍由既有 50 项上限约束。
- 筛选结果不是新的完整性结论；加载、A/B 比较和报告导出仍通过既有安全读取流程重新校验。
- 本阶段不缓存历史文件内容，不改变不可变运行目录或清单格式。

## 7. 关键数值结果 / Numerical results

本阶段不修改优化模型，也未生成新的业务数值结论。历史运行数量上限仍为 50，扫描目录项上限仍为 1000。

## 8. 未解决问题和风险 / Open issues and risks

- 搜索结果仍显示在既有只读下拉框中；表格化浏览、排序和指标预览属于后续阶段。
- 运行产物没有可信运行时间字段，本阶段没有增加或伪造时间排序。
- 具有大量接近上限的历史产物时，显式“刷新运行”的安全读取成本未在本轮压力测量。
