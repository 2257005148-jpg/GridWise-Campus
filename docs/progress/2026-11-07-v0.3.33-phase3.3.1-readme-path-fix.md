## 1. 执行摘要

本阶段修复 Phase 3.3 独立审查确认的 README 安装说明阻断项。原安装代码块把 `[LOCAL_ENV_ROOT]` 当作路径占位符，但没有定义或说明替换方式；PowerShell 会把它解析为字面相对路径，复制执行可能在仓库中创建错误目录。

修复后：

- 使用仓库根目录下的 `.venv`；
- `.venv/` 已由项目 `.gitignore` 排除；
- 不再包含 `[LOCAL_ENV_ROOT]` 或其他未定义路径变量；
- 中英文均说明从仓库根目录执行，并先确认 `python --version` 为 Python 3.12 或更高版本；
- 首条命令使用 `python -m venv .venv`，避免依赖 Windows Python Launcher 对特定运行时的注册；
- 后续命令统一使用 `& .\.venv\Scripts\python.exe ...`，不受仓库父目录空格或本机绝对路径影响。

本阶段仅修改 `README.md` 的安装说明和命令块，并新增本报告。没有修改 LICENSE、第三方声明、贡献指南、项目元数据、产品代码、测试、工作流或依赖。

## 2. 原始问题

原命令示例为：

```powershell
py -3.12 -m venv [LOCAL_ENV_ROOT]\gridwise-campus-py312
& [LOCAL_ENV_ROOT]\gridwise-campus-py312\Scripts\python.exe -m pip install -e .
```

`[LOCAL_ENV_ROOT]` 不是 PowerShell 变量。语法分析显示它会作为普通字符串路径传给命令；正文也没有要求用户替换该占位符。因此该示例不能可靠表达预期安装位置。

## 3. 修复内容

当前安装入口为：

```powershell
python -m venv .venv
& .\.venv\Scripts\python.exe -m pip install -e .
# For development and tests / 用于开发与测试：
& .\.venv\Scripts\python.exe -m pip install -e '.[test]'
```

CLI、CSV 检查、桌面应用、桌面烟雾脚本和独立导出审计命令也统一改用同一个 `.venv` 解释器。除该安装段落外，README 其他技术内容没有在本阶段改写。

随后仅在验证进程的 PATH 中临时把现有完整 Python 3.12.14 放在首位，没有永久修改用户环境：

- `python` 解析到该 Python 3.12.14；
- `import venv` 成功；
- `python -m venv --help` 退出 0；
- 验证结束后恢复原进程 PATH；
- 没有创建虚拟环境，也没有安装、升级或卸载依赖。

因此，README 命令在满足其已声明前提——Windows PowerShell、从仓库根目录执行、`python` 指向完整 Python 3.12 或更高版本——时，可以直接复制执行，不需要替换路径变量。实际 `pip install` 按任务边界未执行。
