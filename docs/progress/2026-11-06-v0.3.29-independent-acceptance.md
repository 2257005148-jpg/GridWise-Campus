### 5.4 阻断问题二：候选工作树 CRLF 导致 LF 审计测试失败

失败测试：

```text
tests/test_audit_exports.py::test_audit_accepts_lf_and_unicode_path
```

失败信息：`summary.run.scenario_sha256: does not match source JSON bytes`。

证据：

- 候选历史 blob 为 LF，但候选当前工作树因系统级 `core.autocrlf=true` 检出为 CRLF。
- 测试先以 CRLF 源文件生成摘要哈希，再把复制文件标准化成 LF，独立审计器按字节正确拒绝哈希不一致。
- 从候选创建 `core.autocrlf=false` 的独立 LF 克隆后，该测试 `1 passed`。
- 从原始备份创建相同 LF 克隆后，该测试也 `1 passed`。

这不是审计器放宽问题；它暴露出仓库没有明确锁定测试夹具的换行契约。最小修复建议是明确仓库换行策略或调整测试夹具生成顺序，使“LF/Unicode 路径”用例从一开始就基于 LF 字节生成摘要。不得放宽场景字节哈希校验。
