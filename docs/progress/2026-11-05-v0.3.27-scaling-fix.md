## 范围 / Scope

本阶段只修复图表 Notebook 在程序化 `tk scaling = 2.0`、窗口 `900×650` 时使用
过期几何请求作出页签标题选择的问题。未修改数据层、求解器、审计器、文件发布、
报告格式、预设格式或其他 UI 业务逻辑。/ This phase only fixes the chart Notebook
tab-title decision that used stale requested geometry at programmatic `tk scaling = 2.0`
and a `900×650` window. The data layer, solver, auditors, file publication, report and
preset formats, and unrelated UI business logic were not changed.

## 根因 / Root cause

`_resize_viewport()` 先恢复完整双语标题，随后立即读取 `winfo_reqwidth()`。Tk 尚未
完成标题变更导致的几何重算，因此首次 Configure 使用旧请求宽度；稍后 Notebook
请求宽度变为 `1508`，但同一宽度不保证再次触发 Configure。/ `_resize_viewport()`
restored the full bilingual titles and immediately read `winfo_reqwidth()`. Tk had not yet
recalculated the geometry requested by those titles, so the first Configure decision used a
stale value. The requested width later became `1508`, without a guaranteed second Configure.

稳定测量还确认：正常缩放下完整标题请求宽度为 `835`；图表 Notebook 可用宽度为
`826`。图表专用页签的水平 padding 从 12 调整为 10 后，完整标题请求宽度可在正常
缩放下容纳。该调整没有改变顶层工作流 Notebook。/ Stable measurement also showed
that full titles requested `835` pixels at normal scaling against `826` available pixels.
Reducing only the chart-tab horizontal padding from 12 to 10 allows the full titles to fit;
the top-level workflow Notebook retains its existing style.

## 修复 / Fix

- 为 `_resize_viewport()` 增加重入保护。
- 恢复完整标题后调用 `update_idletasks()`，仅处理 Tk 待完成的几何任务，再读取请求宽度。
- 若稳定后的请求宽度超过可用宽度，切换为原有紧凑标题并完成几何更新。
- 新增 `Charts.TNotebook` 专用样式，避免影响工作流 Notebook。
- 未增加 `after()`、`after_idle()`、后台任务、sleep、重试或异常吞噬，因此没有新增
  需要在关闭时取消的布局回调。

/ `_resize_viewport()` now has a re-entry guard, waits only for pending Tk geometry work via
`update_idletasks()`, and selects compact titles from the settled request. A chart-specific
Notebook style prevents changes to the workflow Notebook. No timer, background task, sleep,
retry, or Tcl error suppression was introduced.

## 验证内容 / Verified behavior

- scaling 1.0 保留完整双语图表页签。
- scaling 1.5 下 Notebook 请求宽度不超过实际宽度。
- scaling 2.0 自动采用原有紧凑标题。
- 2.0 下反复触发 Configure 不发生标题振荡。
- Ctrl+Tab 可从第一个图表页签到达最后一个 `SOC` 页签。
- 连续打开和关闭三个 2.0 scaling 窗口未出现 Tcl/Tk 异常。
- 每个窗口的既有 `_poll_id` 在关闭后不再存在，解释器的待处理 after 集合未增加。
- 工作流页签、历史滚动、状态显示、键盘操作、诊断详情和关闭清理相邻回归通过。

## 保留的失败与诊断记录 / Preserved failures and diagnostics
