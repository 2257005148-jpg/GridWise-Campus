## 范围 / Scope

本阶段只修复 Phase 1 审计确认的 P1-01：运行中修改 CSV 后，旧 generation
虽被正确隔离，但设备参数、优化策略和预设控件永久保持禁用。未修改报告发布、
数学模型、数据层、运行产物或独立审计器。/ This phase only addresses P1-01:
configuration controls remained disabled after a CSV change invalidated an active run.
Report publication, the mathematical model, data layer, run artifacts and independent
auditors were not changed.

## 根因与修复 / Root cause and fix

- `_start_job()` 通过 `_sync_policy_controls()` 禁用配置和预设控件。
- CSV 或步长变化进入 `_invalidate()`；该函数取消任务、递增 generation、清除
  `_active_kind` 和派生结果，但原先没有重新调用 `_sync_policy_controls()`。
- 旧任务完成事件因 generation 不匹配在 `_poll()` 中丢弃，因此也不会执行正常
  完成路径的控件恢复。
- 最小修复是在 `_invalidate()` 完成活动任务状态清理后复用现有
  `_sync_policy_controls()`。没有新增状态变量、锁、重试或后台任务；generation
  和迟到结果隔离契约不变。

`_configuration_changed()` 原本已正确同步控件。新增设备参数和策略变更测试用于
防止这条既有正确路径退化。/ Device and policy changes already used the correct
control synchronization path; new tests preserve that behavior.

红测失败点为 CSV 变化后设备输入仍处于 `disabled`。修复后，测试确认：

- 活动任务期间设备、策略和六个预设操作均禁用；
- CSV、设备参数或策略变化会设置原取消事件；
- generation 只增加一次，`_active_kind` 清空；
- 控件按当前策略和预设选择恢复正确状态；
- 迟到结果不会改变 generation、恢复旧指标或重新禁用控件；
- CSV 路径变化仍清除输入摘要、指标、图表及单次报告导出资格；
- 设备/策略变化继续保留已通过质量检查的 CSV。

直接相关状态回归还覆盖正常完成、失败、取消、完成后迟到取消、窗口关闭等待、
预设忙碌禁用和迟到诊断隔离。/ Direct regressions also covered completion,
failure, cancellation, late cancellation, close waiting, preset busy-state disabling and
late-result isolation.

## 保留的失败 / Preserved failure

程序化 Tk scaling 为 `2.0`、窗口 `900×650` 时，现有用例
`test_minimum_window_keeps_charts_and_metric_cards_usable_at_dpi_scales[2.0]`
稳定失败：图表 Notebook 请求宽度为 `1508`，实际宽度为 `826`。隔离重跑同样失败。
该问题不在 P1-01 状态恢复范围内，本阶段未修改布局或降低断言。/ The existing
2.0-scaling layout assertion failed reproducibly (`1508 > 826`). It is outside this
state-recovery change and remains unresolved.
