# GridWise Campus v0.3.24 Phase 1 — Preset exchange core / 预设交换格式核心

Date / 日期: 2026-11-02

## Scope / 范围

This phase implements only the versioned single-preset exchange API. It does
not add desktop controls, run a solver or auditor, change the local preset
store format, or modify optimization and artifact contracts.

本阶段只实现版本化的单预设交换 API；未接入桌面按钮，未运行求解器或审计器，
未改变本地预设库格式、优化模型或运行产物契约。

## Implemented / 已实现

- `serialize_preset_exchange(preset) -> bytes`
  - Emits UTF-8 JSON with `ensure_ascii=False` and `allow_nan=False`.
  - Writes only `document_type`, `format_version`, name, the eight device
    parameters and optimization policy. The local preset UUID is omitted.
- `load_preset_exchange(path) -> ScenarioPreset`
  - Reads one bounded regular file, rejects links and junctions, duplicate
    JSON keys, non-UTF-8, non-finite values, unknown versions, wrong document
    types, missing or extra fields, and invalid device or policy values.
  - Reuses `parse_device_parameters()` and `OptimizationPolicy` and assigns a
    fresh UUID. It does not modify the local preset collection or store.
- `export_preset_exchange(store_path, preset_id, target) -> Path`
  - Reloads the validated local store and exports only a preset whose stable
    ID is present there.
  - Publishes a completely written and `fsync`-ed same-directory temporary
    file with `os.link()`. Hard-link creation is atomic and fails when the
    target exists, including a target created between the precheck and final
    publication. `os.replace()` is not used for exchange publication.
  - Reports publication and cleanup failures together, preserves the original
    exception as `__cause__`, and identifies a residual temporary file by its
    absolute path. If publication succeeded but cleanup failed, the error says
    explicitly that the complete target was published.

交换文档格式：

```json
{
  "document_type": "gridwise-scenario-preset",
  "format_version": 1,
  "preset": {
    "name": "教学楼午间削峰",
    "device_parameters": {
      "grid_max_kw": 120,
      "capacity_kwh": 80,
      "initial_kwh": 40,
      "terminal_kwh": 40,
      "max_charge_kw": 30,
      "max_discharge_kw": 30,
      "charge_efficiency": 0.95,
      "discharge_efficiency": 0.95
    },
    "optimization": {
      "mode": "peak_cap",
      "peak_cap_kw": 55
    }
  }
}
```

## Security boundary / 安全边界

- Input and output size is limited to 128 KiB. The existing collection limit
  remains 100 presets; a later UI import must add the returned preset through
  existing collection CRUD rather than bypassing that limit.
- Import is read-only. Validation completes before a `ScenarioPreset` is
  returned, and no local preset file is written by the import API.
- The reader compares path and opened-file identity and checks the open file
  before and after reading. Link/junction checks are repeated around I/O.
- Export uses an exclusive private temporary file and atomic, no-overwrite
  hard-link publication. A filesystem that does not support the operation
  fails closed rather than falling back to an overwriting rename.
- The export contains no generated CSV path, user path, run result, report
  path or run-history field. A user-supplied preset name is retained verbatim
  and could itself contain user-entered personal text.
- These checks do not form a sandbox against a privileged malicious local
  process that continuously replaces ancestor directories. Multi-process
  preset-store writes and power-loss durability of the directory entry are
  not guaranteed. File contents are `fsync`-ed; the directory is not.
